Passkey RP ID / Public Suffix Test

Calls navigator.credentials.create() and .get() with RP IDs that a conforming WebAuthn implementation must refuse, such as public suffixes (github.io, io, co.uk) and unrelated domains. Use it with your password-manager extension active to see whether the extension enforces the same RP ID rules as the browser.

This page is not in a secure context. WebAuthn needs HTTPS (or localhost). Open it from its https:// URL.

Environment

How to read results

  • Expected: reject. A SecurityError (or TypeError) is a PASS. If a credential or assertion is returned, that is a FAIL: the extension (or browser) accepted an RP ID it should not have.
  • NotAllowedError is inconclusive. It means a prompt was cancelled or timed out. Watch whether the extension showed a "save passkey for …" UI for the disallowed RP ID, and retry.
  • For each issued credential the page also checks that rpIdHash in authenticatorData equals SHA-256 of the requested RP ID and that clientDataJSON.origin equals this page's origin.
  • Run Create for the baseline first so Get has a passkey to find. Browsers may require a click for each call, so if "Run all" stops with NotAllowedError, click the rows individually.

Custom RP ID

Related Origin Requests and secondary RP ID

An RP ID that is not a suffix of this origin is only valid through Related Origin Requests: the browser fetches https://<rpId>/.well-known/webauthn and accepts the RP ID only if this page's origin is listed there. An extension that skips that check must not hand out credentials for such an RP ID. This field is also "RP B" for the cross-RP tests below, so use either a parent domain you control (when this page is on a custom domain) or a related-origin domain whose file you can edit. Browsers also cap how many distinct sites the file may list (about five).

JSON to host on the related domain (positive test) 

    
Serve it at /.well-known/webauthn on the secondary domain, with no redirects and
       Content-Type: application/json. Some static hosts (GitHub Pages included) may serve extensionless files as
       application/octet-stream, in which case use a host where you can set headers. For the negative test, host a
       file that omits this origin, or no file at all, and set Expected to "Must be rejected".

  


  
Cross-RP credential tests (allowCredentials / excludeCredentials)

  
A credential ID belongs to exactly one RP. An authenticator must ignore IDs bound to another RP, and it must validate the
     RP ID before it looks at allowCredentials or excludeCredentials. An extension that matches by
     credential ID alone would use a passkey for the wrong RP, or reveal that a passkey exists for another site
     (InvalidStateError where none is expected). Create a credential for RP A (this host) first. Tests that involve a second
     RP also need RP B from the section above.

Iframe tests

  
Checks that the extension respects the same boundaries as the browser inside frames. A sandboxed frame has an opaque origin and
     must not get any RP ID. A cross-origin frame needs delegation through the allow attribute (Permissions Policy), and its RP ID must be
     valid for the frame's own origin, not the embedding page's. Browsers need a click inside the frame, so each test opens a frame
     and you press the button shown in it.
